# Document Lens — context for agents

VS Code extension (`thai1108.document-lens`, public, MIT) that previews `.pdf`, `.docx`, `.doc`, `.xlsx`, `.xls`,
`.pptx`, `.ppt` read-only in a sandboxed webview. Read this file instead of exploring the repo; open the files it
names only when your task touches them.

## Architecture

- **Host** (`src/`, Node, bundled to `dist/extension.cjs`):
  - `documentProvider.ts`: one `CustomReadonlyEditorProvider` per format; reads the file, applies the size cap and
    preflight check, watches it on disk (debounced reload; keeps the last good version if a reload fails), and posts
    the bytes.
  - `formats/<id>.ts` + `formats/index.ts` (`FORMATS`): `id`, extensions, `maxFileSize`, `webview` (bundle name),
    `csp` extras, `findWidget`, `check(bytes)`. `package.json` declares the same `customEditors`;
    `test/formats.test.ts` fails if they drift.
  - `preflight.ts`: signatures (PDF header, compound file, ZIP), OOXML package check via `zip.ts`.
  - `zip.ts`: strict ZIP reader. It refuses archives other readers (JSZip) would see differently: prepended data,
    non-canonical/duplicate names, mismatched local headers, overlaps, ZIP64.
  - `limits.ts`: all shared caps (file sizes, OOXML ZIP limits, `MAX_XML_PART_SIZE`, `MAX_PDF_PAGES`). No Node
    imports: the webview uses it too.
  - `protocol.ts`: host↔webview message types; `parseWebviewMessage` validates everything from the webview
    (`ready`, `openLink` http(s) only).
  - `payload.ts`: bytes go out as a plain, exactly-sized `Uint8Array` (a Node Buffer would arrive as
    `{type:'Buffer',data:[…]}`).
  - `webviewHtml.ts`: page + strict CSP: `default-src 'none'`, script nonce, style `cspSource` + nonce, img/font
    `blob: data:`. Formats add sources only through `FormatDefinition.csp`.
- **Webview** (`src/webview/`, browser, one bundle per folder → `dist/webview-<name>.js/.css`):
  - `shell/app.ts`: `startViewer(viewer)` builds toolbar, banners and `#content`, and handles zoom, keys, link
    interception and state.
    - `Viewer`: `render(document, context, reload)`, optional `applyZoom`, `fitWidthZoom`.
    - `ViewerContext`: `content`, `tools`, `styleNonce`, `zoom/setZoom`, `viewerState/saveViewerState`,
      `showNotice`, `showSimplifiedNotice`, `showError`, `openLink`.
  - Viewers:
    - `pdf/`: pdf.js 6, embedded worker/CMaps/fonts/wasm, own toolbar and find.
    - `docx/`: docx-preview + JSZip-consistent ZIP check, DOM/CSS sanitizer, media cache, budgets.
    - `doc/`: own CFB + piece-table reader.
    - `spreadsheet/`: `.xlsx` own streaming reader, `.xls` via SheetJS CE tarball + own BIFF style scan;
      format-neutral sheet model (`SheetBuilder`, `readCell`), virtual grid, `view/selection.ts`.
    - `pptx/`: own DrawingML renderer (theme, inheritance, geometry, text, tables, budgets).
    - `ppt/`: own CFB + record parser.
  - Bundle options for one viewer go in `src/webview/<name>/build.mjs` (merged over `esbuild.mjs`). Third-party
    license texts are emitted next to the bundle (`dist/webview-*.licenses.txt`).

## Rules for every change

- Files are hostile.
  - Cap counts, sizes, nesting and total work, and count *work done*, not just declared sizes.
  - No script execution, no remote loads, sanitize library HTML, text via `textContent`.
  - Links only through `context.openLink`.
  - No `style="…"` attributes in generated markup (CSP); use classes, CSSOM, SVG presentation attributes or
    `<style nonce>`.
- TypeScript 6 with `erasableSyntaxOnly`: no enums, namespaces or parameter properties. Use `.ts` import extensions,
  English, and comments only for a non-obvious why. Match the surrounding code.
- Dependencies: MIT/Apache-2.0/BSD/ISC only, exact version published ≥ 2 weeks earlier, `pnpm audit`, and license
  text shipped if bundled. `xlsx` comes from the cdn.sheetjs.com tarball with a hand-added `integrity` in
  `pnpm-lock.yaml`; a test checks it, so keep it when regenerating the lockfile.
- Never commit real documents or anything derived from them (fixtures, screenshots). Real files in `~/Downloads`,
  `~/Desktop` and `~/Documents` may be client data: use them locally only (`E2E_FILES`, `pnpm preview` into the
  scratchpad), report counts and pass/fail only, and never save edits into them.

## Tests and gates

- Layers:
  - unit, `node:test` with `.ts` stripping: `test/**/*.test.ts`;
  - happy-dom: `test/webview/**`, booted with `test/webview/dom/env.ts` (no layout);
  - Playwright in the installed Chrome: `test/e2e/<viewer>.spec.ts`, via `servePreview()`, `watchProblems()` and
    `expectShellLoaded()` from `test/e2e/preview-server.ts` (real page + CSP + VS Code serializer mock;
    `window.previewReload()`, `window.previewLinks`);
  - VS Code: `test/vscode/<viewer>.suite.ts`, fixtures written by `make-fixtures.ts`.
- Samples are generated by code: `test/fixtures/<id>.ts` exports `samples`, built with the helpers in
  `test/support/` (zip, ooxml, pdf, cfb, word, ppt, pptx, xlsx and biff writers, `png.ts`). `test/e2e/shell.spec.ts`
  requires every format's sample to render without an error banner.
- Gates before any PR, all must pass: `pnpm check`, `pnpm test:e2e`, `pnpm test:vscode`, `pnpm package` (then delete
  the `.vsix`).
- Visual check: Playwright screenshots into the session scratchpad, then look at them.

## Workflow

- Every `gh` call: `GH_TOKEN=$(gh auth token --user thai1108) gh … --repo thai1108/vscode-document-lens` (the active
  gh account is another one). Remote: `git@github.com-thai1108:thai1108/vscode-document-lens.git`. Git identity:
  `thai1108 <vietthai1108@gmail.com>`. No co-author or AI attribution.
- One issue per change.
  - Branch `<type>/#<id>-<slug>` from `origin/main` with `--no-track`; check that `@{upstream}` is unset.
  - Commits `[#<id>] …` in English, under 100 characters; publish with `git push -u origin HEAD`.
  - PR body: `## Summary` bullets, then `Issue: #<id>` (no fixes/closes keywords). Squash subject:
    `[#<id>] <title> (#<pr>)`.
- Agents open PRs but do not merge, and do not edit `README.md`/`CHANGELOG.md` (propose the text under "Docs" in
  the PR body). Bring a branch up to date by merging `origin/main` into it; never force-push.
- `rm -rf` is blocked by a hook; delete specific files. Work in your own worktree, never in another agent's.
